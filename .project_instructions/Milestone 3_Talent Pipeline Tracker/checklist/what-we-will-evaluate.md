# What We Will Evaluate — Milestone 3

- [ ] Candidate list page renders data fetched from the API
- [ ] Filters by status and stage work using query parameters (no full page reload)
- [ ] Search by name or email works without reloading the page
- [ ] Detail page loads and displays all fields for the correct candidate by ID
- [ ] Status and stage can be updated from the detail view using PATCH
- [ ] Notes can be listed, added, and deleted from the detail view
- [ ] New candidates can be registered via a form using POST
- [ ] Existing candidate data can be edited via a form using PUT
- [ ] Loading, success, and error states are visible for all async operations
- [ ] TypeScript types are defined and used for API data structures
- [ ] Folder structure separates components, types, and data access logic
- [ ] Next.js App Router is used correctly for navigation and dynamic routes
- [ ] No prop drilling — component state is scoped appropriately
- [ ] UI reflects the company scenario from CONTEXT.md (labels, terminology, framing)

Note: Visual design is not formally evaluated; the UI must be usable and clear.
